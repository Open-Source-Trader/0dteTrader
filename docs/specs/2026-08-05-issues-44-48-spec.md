## 2. Problem Statement

The chart indicators are duplicated and drifting across desktop and iOS, market data has no truthful Level 2 contract, ATM IV does not interpolate at spot and cannot drive durable anomaly alerts, and Auto contract selection is an offset ladder rather than an explainable scorer. These gaps can produce inconsistent client behavior, fabricated zero states, missed alerts, and contract choices that are not revalidated against fresh quotes.

The desired outcome is one shared set of public contracts, deterministic pure calculations with cross-platform parity, bounded server-side state, clear unavailable states, and safe order confirmation behavior.

## 3. Goals And Non-Goals

### Goals

- Make a shared JSON indicator registry the canonical source for desktop and iOS indicator identity, parameters, styles, panes, and generic geometry.
- Add the approved indicator suite while preserving the existing TWC behavior and enforcing two subpanes everywhere.
- Add truthful, entitlement-aware Webull Level 2 ingestion and derived microstructure indicators without changing Tradier beyond Level 1.
- Correct ATM IV to use paired-strike values and exact-or-linear spot interpolation, then persist it and detect restart-safe expansion/crush anomalies per user and symbol.
- Add deterministic scored Auto selection with persisted presets, explanations, explicit fallback acknowledgment, server-side fresh revalidation, and mandatory confirmation.
- Remove replaced settings, dispatch, UI, and compatibility paths after their one-time data migration has run.

### Non-Goals

- Reconstructing or implementing deleted issue #46.
- Changing the TWC calculation or presentation contract.
- Adding Level 2 to Tradier, options depth, order-book replay, or historical Level 2 storage.
- Extrapolating ATM IV outside paired strikes or substituting a one-sided option leg.
- Adding IV chart markers; dismissible banners are sufficient.
- Silently falling back from scored Auto to Classic, or changing existing Classic `auto_otm` confirmation behavior.
- Treating simulator measurements as a substitute for the required physical-iPhone Energy Log.

## 4. Scope

### In scope

- `packages/shared-types`, API market-data/options-analytics/trading modules, Prisma schema and migration.
- Desktop and iOS chart engines, settings, renderers, socket clients, IV alerts, contract selectors, trade panels, profile/preferences, tests, and project resources.
- OpenAPI, architecture, API, runbook, privacy, and operational documentation impacted by the new contracts.

### Out of scope

- Provider purchases or entitlement approval on the user's behalf.
- Posting the required GitHub #45 capability comment without authenticated GitHub credentials.
- Physical-device execution when no device is connected; this remains a completion gate rather than being waived.

## 5. Context And Dependencies

- Desktop currently imports TypeScript settings and manually dispatches/render indicators; iOS carries a separate Swift settings/engine implementation.
- `apps/api/src/market-data/stream.gateway.ts` currently transports quote messages only.
- Webull supports stock/ETF depth only when the application has Nasdaq TotalView Non-Display OpenAPI entitlement. Its documented HTTP depth limit is one request per second per app key.
- Tradier streaming remains Level 1 only.
- Options analytics already captures snapshots, but its ATM IV chooses a nearest strike instead of exact-or-interpolated paired-strike IV.
- Selection mode currently supports `auto_otm` and explicit contracts; client settings are local while authenticated per-user server persistence is required for the new modes.
- NY trading-session time, RTH, DST, early-close behavior, database availability, broker freshness, and websocket identity are upstream constraints.

## 6. Requirements

### Shared indicator platform (#44)

- **REQ-044-001 — Canonical registry (must).** A versioned JSON registry in `packages/shared-types` defines indicator id, display name, pane class, typed parameter schema, style tokens, and generic geometry; desktop imports it and iOS bundles and decodes the same file. Validation: schema and both-client decode tests.
- **REQ-044-002 — Keyed settings migration (must).** Indicator settings are stored as a keyed record by registry id. A one-time migration reads the prior flat shape and writes the new shape; `volumeEnabled` moves to a separate chart-display preference. Old runtime/UI settings paths are deleted after migration. Validation: migration idempotency and residue tests.
- **REQ-044-003 — Generic execution and rendering (must).** Registry geometry drives generic line, multi-line, band, cloud, histogram, segmented-line, and price-profile outputs and controls on both clients, replacing per-indicator dispatch and pane duplication. Validation: descriptor-to-engine-to-renderer coverage.
- **REQ-044-004 — Indicator suite (must).** Implement Anchored VWAP (`0` means session anchor; a timestamp means user anchor), Supertrend, Keltner Channels, VPVR, ADX/DMI, OBV, CCI, Williams %R, and Ichimoku. TWC remains behaviorally unchanged. Validation: deterministic vectors, edge cases, and snapshots.
- **REQ-044-005 — Pane limit (must).** Desktop and iOS enforce `MAX_SUB_PANES = 2` at mutation and render boundaries and show the same clear message when a third distinct subpane is requested. Validation: paired UI/settings tests.
- **REQ-044-006 — Numeric parity (must).** Both engines produce finite values that match shared fixture expectations within `1e-6`. Validation: TypeScript and Swift tests consume the same fixture.

### Level 2 market data (#45)

- **REQ-045-001 — Public contracts (must).** Shared types define `OrderBookLevel`, `OrderBookSnapshot`, subscribe/unsubscribe/status/data websocket messages, freshness, provider, timestamp, symbol, bids, and asks. Validation: compile-time and payload decoder tests.
- **REQ-045-002 — Provider seam and entitlement (must).** A dedicated order-book provider interface supplies Webull stock/ETF depth and probes entitlement. Tradier remains Level 1. Unsupported instruments and missing entitlement yield explicit unavailable reasons. Validation: provider and gateway tests.
- **REQ-045-003 — Rate and lifecycle safety (must).** Webull HTTP depth is globally limited across API replicas to one request/second/app key by a Redis atomic lease/token-bucket key; local queues may schedule work only after the distributed grant. Overlapping work is coalesced, per-symbol output is capped, subscribers and timers are isolated from L1, and all work tears down from every active state on last unsubscribe, disconnect, terminal provider failure, shutdown, or NY-session reset. Validation: fake-clock concurrency/lifecycle tests plus a multi-instance Redis integration test.
- **REQ-045-004 — Session state (must).** The server keeps bounded quote/book history for the current New York session, resets on the NY trading-day boundary, and marks book data stale after five seconds. Validation: DST/day-boundary and bounds tests.
- **REQ-045-005 — Derived indicators (must).** Pure calculations expose absolute and basis-point spread, session spread percentile, top-book imbalance, tick pressure, configurable N-level depth imbalance, cumulative pressure, and touch depletion. Validation: golden fixtures including crossed, empty, equal, and partial books.
- **REQ-045-006 — Truthful clients (must).** Missing, stale, unsupported, or unentitled data displays `No L2 data` with a reason; it is never converted to numeric zero. Validation: paired client presentation tests.
- **REQ-045-007 — Operations and completion evidence (must).** Add request, rate-limit, coalescing, subscriber, staleness, entitlement, payload-size, and decoder-time metrics/logs. Record automated payload/decoder measurements, a 15-minute physical-iPhone Energy Log, and an authenticated capability result comment on GitHub #45. Validation: test output, device artifact, and issue-comment URL.

### ATM IV anomaly alerts (#47)

- **REQ-047-001 — ATM IV calculation (must).** For each strike with both a call and put IV, compute their arithmetic mean. If spot exactly matches a paired strike, use that value; otherwise linearly interpolate between the nearest paired strikes bracketing spot. Never extrapolate and never use a missing-leg fallback. Validation: exact, interpolation, missing-leg, no-bracket, and ordering tests.
- **REQ-047-002 — Snapshot storage (must).** Bump the analytics calculation version and add nullable indexed `atmIv` to the snapshot record through a Prisma migration. Validation: generated client, schema validation, migration, read/write tests.
- **REQ-047-003 — Persisted per-user state (must).** Prisma stores authenticated per-user alert preferences and per-user/symbol detector state. Symbols are independently keyed for SPX, NDX, and RUT. Validation: uniqueness/isolation tests.
- **REQ-047-004 — Detector (must).** A pure median/MAD detector runs RTH only with defaults: 30-minute lookback, `k=3`, two consecutive breaches, 10-minute and at least 10-sample warmup, five-minute cooldown, and reset after a gap greater than two capture intervals. It emits expansion or crush; a zero MAD yields a finite clamped score. Validation: fake-clock golden state-machine tests.
- **REQ-047-005 — Restart and delivery safety (must).** Process only captures newer than persisted state, persist timestamp/streak/direction/cooldown atomically, and prevent restart/backfill bursts. `ivAlertConfigure` persists preferences and authenticated `ivAlert` messages are user-scoped. Validation: restart, duplicate, reconnect, and authorization tests.
- **REQ-047-006 — Client alerts (must).** Desktop and iOS show dismissible, nonblocking banners with symbol, direction, ATM IV, baseline, and time. Validation: paired UI and accessibility tests.

### Scored Auto selection (#48)

- **REQ-048-001 — Modes and preferences (must).** Add `auto_scored`; retain `auto_otm` as Classic +1. Supply the numeric Conservative and Aggressive presets defined below plus validated editable preferences persisted per authenticated user in versioned Prisma state. Remove the old standalone Auto-offset setting and UI. Validation: migration/defaults/preferences/residue tests.
- **REQ-048-002 — Candidate assembly (must).** An authenticated API path merges Tradier analytics with active-broker executable quotes for the selected symbol. Missing required quote/Greek/OI fields excludes a candidate. Validation: authorization, merge, partial-data, and freshness tests.
- **REQ-048-003 — Pure deterministic scorer (must).** API, desktop, and Swift implementations first filter requested expiration, option type, and strike rungs; use absolute put delta; compute spread bps as `(ask-bid)/mid*10000` and max premium as `mid*100`; apply hard filters before scoring; normalize to `[0,1]` with equal-valued dimensions receiving equal contributions; seek or avoid absolute gamma as configured; value lower IV relative to candidate median; and retain full precision. Ties break by score, narrower spread, higher open interest, smaller ATM distance, then symbol. Validation: shared golden fixtures and property tests.
- **REQ-048-004 — Explainable results and fallback (must).** Clients show the winner's rationale and runners-up. If none pass, show a warning; Classic fallback requires explicit acknowledgment and is never silent. Validation: paired presentation/state tests.
- **REQ-048-005 — Server authority and confirmation (must).** Requests include selected symbol, preferences, and fallback acknowledgment. Immediately before order acceptance the server fetches fresh inputs, reranks, revalidates, and rejects stale or invalid selection. Every scored-Auto order requires explicit confirmation even if the global bypass is enabled; Classic remains unchanged. Validation: trading-service e2e tests covering races and bypass.

### Normative calculation, default, and persistence contracts

#### Indicator settings branches

- If a valid current-version keyed settings record exists, validate every id/parameter and use it.
- Else if a recognized flat legacy record exists, map recognized values, fill missing values from registry defaults, move `volumeEnabled`, atomically write/re-read the keyed record, then delete the legacy key.
- Else create registry defaults with no more than two enabled subpanes.
- Unknown ids/parameters, out-of-range values, registry/version errors, or any non-finite input/output reject the candidate mutation and preserve the last valid settings; no partial geometry renders.

#### Indicator defaults, migration map, and formulas

- Registry version `1` contains these retained indicators and defaults: SMA `{enabled:false, period:20}`, EMA `{enabled:true, period:9}`, RSI `{enabled:false, period:14}`, MACD `{enabled:false, fastPeriod:12, slowPeriod:26, signalPeriod:9}`, Bollinger `{enabled:false, period:20, multiplier:2}`, Stochastic `{enabled:false, kPeriod:14, kSmooth:3, dPeriod:3}`, and ATR `{enabled:false, period:14}`. Existing formulas retain their current tested behavior.
- Registry version `1` contains these new or upgraded indicators and defaults: Anchored VWAP `{enabled:true, anchorTimestamp:0}`, Supertrend `{enabled:false, atrPeriod:10, multiplier:3}`, Keltner `{enabled:false, emaPeriod:20, atrPeriod:10, multiplier:2}`, VPVR `{enabled:false, rowCount:24, valueAreaPercent:70}`, ADX/DMI `{enabled:false, period:14}`, OBV `{enabled:false}`, CCI `{enabled:false, period:20}`, Williams %R `{enabled:false, period:14}`, and Ichimoku `{enabled:false, conversionPeriod:9, basePeriod:26, spanBPeriod:52, displacement:26}`. Volume display defaults to enabled but is not an indicator registry entry.
- Registry version `1` also contains disabled subpane microstructure entries consumed by both clients: Spread with fixed session absolute/bps/percentile multi-line geometry, Top Book Imbalance, fixed-60-second Tick Pressure, Depth Imbalance `{levels:5}`, fixed-60-second Cumulative Pressure `{levels:5}`, and Touch Depletion. Only the depth-based entries expose a parameter: `levels` is an integer `1...50` additionally clamped to published depth. The fixed windows are part of the version-1 calculation contract, not editable settings. L2-dependent entries render the explicit unavailable state from REQ-045-006 instead of geometry when the current book is missing or stale.
- Integer period bounds are `1...500`; MACD additionally requires `fastPeriod < slowPeriod`; multiplier bounds are finite `0.1...20`; VPVR row count is `4...200`; value-area percent is finite `1...100`; anchor timestamp is `0` or a positive Unix-millisecond candle timestamp; Ichimoku displacement is `1...500`.
- Legacy mapping is exact and one-way: `smaEnabled/smaPeriod -> sma`, `emaEnabled/emaPeriod -> ema`, `vwapEnabled -> anchored_vwap` with anchor `0`, `rsiEnabled/rsiPeriod -> rsi`, `macdEnabled/macdFastPeriod/macdSlowPeriod/macdSignalPeriod -> macd`, `bollingerEnabled/bollingerPeriod/bollingerMultiplier -> bollinger`, `stochEnabled/stochKPeriod/stochKSmooth/stochDPeriod -> stochastic`, `atrEnabled/atrPeriod -> atr`, and `volumeEnabled -> chartDisplay.volumeEnabled`. Missing legacy fields use registry defaults; unknown legacy fields are discarded after the successful atomic migration.
- Every candle supplied to the new engines has a strictly increasing Unix-millisecond timestamp and finite OHLCV values with `high >= max(open,close,low)`, `low <= min(open,close,high)`, and volume at least zero. Invalid input rejects the whole calculation.
- True range is `max(high-low, abs(high-previousClose), abs(low-previousClose))`; for the first candle it is `high-low`. Wilder ATR seeds at index `period-1` with the arithmetic mean of the first `period` true ranges and then uses `(previousATR*(period-1)+TR)/period`.
- Anchored VWAP uses typical price `(high+low+close)/3`. Anchor `0` starts at the first candle in the current New York session; a user anchor starts at the first candle whose timestamp is at or after the exact persisted timestamp. Earlier output is null. Each later value is cumulative `sum(typicalPrice*volume)/sum(volume)` and is null until cumulative volume is positive.
- Supertrend uses `hl2=(high+low)/2`, basic bands `hl2 +/- multiplier*ATR`, final upper equal to the basic upper when it is below the prior final upper or prior close is above the prior final upper (otherwise retain prior), and final lower symmetrically when the basic lower is above the prior final lower or prior close is below it. At the first finite ATR, direction is bullish when `close >= hl2`, otherwise bearish. A bearish bar flips bullish only when close is above the prior final upper; a bullish bar flips bearish only when close is below the prior final lower. Bullish output uses final lower, bearish output uses final upper, and the opposite segment is null.
- Keltner center is the existing seeded EMA of close; upper/lower are `center +/- multiplier*WilderATR`, null until both components are finite.
- VPVR spans the minimum low through maximum high of the supplied visible window. Equal high/low produces one effective row. Otherwise row width is `(maxHigh-minLow)/rowCount`; bins are half-open except the last includes `maxHigh`. Each candle assigns all its volume to the bin containing its typical price. Value-area rows are chosen by descending volume with lower-price-row tie break until cumulative selected volume is at least `totalVolume*valueAreaPercent/100`. Geometry returns ordered low/high/volume/value-area rows.
- ADX/DMI begins at bar 1: `upMove=high_i-high_(i-1)`, `downMove=low_(i-1)-low_i`, `+DM=upMove` only when it is positive and greater than downMove, and `-DM=downMove` only when positive and greater than upMove. Seed Wilder sums of TR/+DM/-DM across bars `1...period`; update each sum as `prior-prior/period+current`; `+DI/-DI=100*DM/TR`, and `DX=100*abs(+DI-(-DI))/(+DI+(-DI))` with zero denominator producing zero. The first ADX at index `2*period-1` is the arithmetic mean of the first `period` DX values and later ADX uses Wilder recursion.
- OBV starts at zero; each later bar adds volume when close rises, subtracts volume when close falls, and is unchanged on an equal close.
- CCI uses typical price, its trailing-period SMA, and mean absolute deviation across the same window: `(typical-SMA)/(0.015*meanDeviation)`; zero mean deviation yields zero.
- Williams %R is `-100*(highestHigh-close)/(highestHigh-lowestLow)` over the trailing period; a zero range yields `-50`.
- Ichimoku conversion and base lines are trailing high/low midpoints for their periods. Leading span A is `(conversion+base)/2` written `displacement` bars forward; leading span B is the span-B-period midpoint written forward; lagging span is close written `displacement` bars backward. Out-of-range or warmup cells are null, and the cloud is the finite span-A/span-B pair.
- Warmup outputs are null, not zero. All engines preserve input alignment except VPVR's explicitly price-binned geometry, and no engine rounds before serialization or comparison.

#### L2 formulas, windows, ties, and resets

- A valid book requires finite positive prices, finite nonnegative sizes, sorted bids/asks, both sides present, and `bestAsk >= bestBid`. Otherwise every derived value is unavailable.
- `mid = (bestAsk + bestBid) / 2`; `spreadAbs = bestAsk - bestBid`; `spreadBps = spreadAbs / mid * 10000` when `mid > 0`.
- Spread percentile compares the current spread to at most the prior 23,400 valid one-second samples in the same NY RTH session: `100 * (count(prior < current) + 0.5 * count(prior == current)) / priorCount`. It is unavailable when `priorCount = 0`.
- Top-book imbalance is `(bestBidSize - bestAskSize) / (bestBidSize + bestAskSize)`; a positive-denominator size tie is `0`, and a zero denominator is unavailable.
- Tick pressure is the arithmetic mean of `sign(mid_i - mid_(i-1))` over valid updates in the trailing 60 seconds; unchanged mids contribute `0`, and no comparison is unavailable.
- For configured `N` clamped to `1...publishedDepth`, depth imbalance is `(sumBidSize_N - sumAskSize_N) / (sumBidSize_N + sumAskSize_N)`; a positive-denominator tie is `0`, and a zero denominator is unavailable.
- Cumulative pressure uses the same N-level totals over the trailing 60 seconds: numerator `sum((B_i-B_(i-1)) - (A_i-A_(i-1)))`, denominator `sum(abs(B_i-B_(i-1)) + abs(A_i-A_(i-1)))`; denominator zero is `0` when comparisons exist and unavailable otherwise.
- Touch depletion for an unchanged touch price is `max(previousSize-currentSize, 0)` per side; a changed touch contributes zero for that side. Net touch depletion is `(askDepletion-bidDepletion)/(askDepletion+bidDepletion)`, where positive means buy pressure; a zero denominator is `0` when a comparison exists and unavailable otherwise.
- Histories and derived windows reset at the NY session boundary. A stale/invalid/missing book does not append a numeric sample and is displayed as `No L2 data`.

#### ATM IV detector

- The normative capture interval is one minute. A gap is reset only when `currentTimestamp-lastProcessedTimestamp > 2 minutes`; exactly two minutes is continuous. A reset clears pre-gap baseline samples, direction, and streak before the current sample is stored.
- The lookback baseline uses prior valid RTH samples with timestamps in the half-open interval `[currentTimestamp-30 minutes, currentTimestamp)`; the current sample is excluded. RTH uses the exchange calendar for 09:30 inclusive through the day's official close exclusive in `America/New_York`, including holidays and early closes. Raw MAD is `median(abs(x_i - median(x)))` with no consistency multiplier.
- Warmup requires both at least ten prior samples and `currentTimestamp-firstPostResetValidSampleTimestamp >= 10 minutes`.
- For `MAD > 0`, signed score is `(current - median) / MAD`, clamped to `[-20, 20]`. For `MAD = 0`, score is `0` when current equals median, `+20` when greater, and `-20` when lower.
- Expansion breaches `score >= +k`; crush breaches `score <= -k`. A non-breach or direction change resets the streak to zero or one for the new direction. Two consecutive means two adjacent eligible captures of the same direction.
- Cooldown suppresses alerts while `captureTimestamp < cooldownUntil`; suppressed captures still update bounded baseline history and last-processed timestamp but force direction null and streak zero, so cooldown breaches never pre-arm a later alert. A capture exactly at `cooldownUntil` is eligible. The emitted banner includes the baseline median used for that decision.

#### Scored Auto defaults and math

- Conservative preset: target absolute delta `0.25`, strike rungs `5`, max spread `500` bps, max premium `$250`, minimum OI `100`, gamma mode `avoid`, weights delta/spread/OI/gamma/IV = `0.30/0.25/0.20/0.10/0.15`.
- Aggressive preset: target absolute delta `0.40`, strike rungs `8`, max spread `1000` bps, max premium `$500`, minimum OI `25`, gamma mode `seek`, weights `0.25/0.15/0.15/0.30/0.15`.
- `strikeRungs` is an integer `0...20`. Build ascending unique strikes for the requested expiration and option type. The ATM anchor is the strike with minimum absolute distance to spot; an exact distance tie chooses the higher strike for a call and lower strike for a put. The candidate window includes the ATM anchor plus at most `strikeRungs` distinct strikes below and at most `strikeRungs` above, so `0` means ATM only.
- Editable preferences require schema version `1`, preset `conservative`, `aggressive`, or `custom`; target absolute delta finite in `[0.01,0.99]`; max spread finite in `[0,10000]` bps; max premium finite in `(0,1000000]` dollars per contract; minimum OI an integer in `[0,1000000000]`; gamma mode `seek` or `avoid`; every weight finite in `[0,1]`; and a finite positive weight total. Weights are normalized by dividing by the total before aggregation. Any invalid preference rejects the request; hard filters run first.
- Executable quote input requires finite `bid >= 0`, finite `ask > 0`, `ask >= bid`, and a provider timestamp. The scorer derives `mid=(bid+ask)/2` itself and requires `mid > 0`; a provider-supplied mid is ignored. Analytics requires finite delta, gamma, IV at least zero, and integer OI at least zero. Missing or inconsistent values exclude the candidate with a reason.
- Raw desirability is: delta `-abs(abs(delta)-targetAbsDelta)`; spread `-spreadBps`; OI `openInterest`; gamma `abs(gamma)` for seek and `-abs(gamma)` for avoid; IV `median(candidateIV)-candidateIV`, with the median computed across passing candidates.
- Each raw dimension is min-max normalized so higher is better. If its domain is constant, every candidate receives `1` for that dimension. Final score is the weighted sum of normalized dimensions using full precision.
- Candidate quote age must be at most five seconds at ranking and reranking, its provider timestamp must not exceed server time by more than two seconds, and analytics age must be at most 60 seconds. Otherwise the candidate is excluded/rejected.
- The acknowledged Classic fallback uses the existing `auto_otm` +1 resolution and confirmation rules and never enters scored reranking. The scored path always reranks and always requires explicit scored confirmation.

#### Auto preference persistence

- Prisma adds `AutoScoringPreference`: `id String @id @default(uuid()) @db.Uuid`, `userId String @db.Uuid`, `user User @relation(fields:[userId], references:[id], onDelete:Cascade)`, `schemaVersion Int @default(1)`, `preset String`, `targetAbsDelta Float`, `strikeRungs Int`, `maxSpreadBps Float`, `maxPremiumDollars Float`, `minOpenInterest Int`, `gammaMode String`, `deltaWeight Float`, `spreadWeight Float`, `openInterestWeight Float`, `gammaWeight Float`, `ivWeight Float`, `createdAt DateTime @default(now())`, `updatedAt DateTime @updatedAt`, `@@unique([userId])`, and `@@map("auto_scoring_preferences")`; `User` gains the optional relation.
- The authenticated create DTO uses the exact camel-case preference field names above and omits concurrency metadata. The update DTO adds required `expectedUpdatedAt`, an ISO-8601 string copied from the last successful read; the server transaction updates only where both `userId` and `updatedAt=expectedUpdatedAt`, returning HTTP 409 when the update count is zero. Unknown fields are rejected and normative bounds run before persistence. Database check constraints enforce schema version `1`, allowed preset/gamma strings, all numeric bounds, and positive total weight.
- The migration creates the table, foreign key, and unique index transactionally. Existing users receive no eager row; first authenticated read materializes the Conservative v1 default. Any unsupported stored schema version is rejected and surfaced for migration rather than silently interpreted.

## 7. User/System Flows

### Primary flows

1. A client loads the canonical indicator registry, migrates settings once, validates the pane limit, computes generic geometry, and renders the enabled indicators.
2. An authenticated client subscribes to L2. The gateway validates symbol/capability, coalesces a rate-limited Webull request, publishes a bounded fresh snapshot, derives indicators, and tears down when unused.
3. A new RTH analytics capture persists interpolated ATM IV, advances the user's detector state, and emits a scoped banner only after warmup, streak, and cooldown guards pass.
4. A user chooses scored Auto, edits or selects a preset, inspects rationale, confirms, and the server reranks against fresh broker inputs before accepting the order.

### Alternate/error flows

- Unknown registry entries, invalid parameters, non-finite outputs, or a third subpane are rejected with a stable client-visible message.
- Missing entitlement, unsupported symbol, provider failure, stale book, empty side, or disconnect produces `No L2 data`; timers and provider work are released.
- Missing ATM legs/brackets persist a null snapshot but do not mutate detector state. Closed-session, unsupported-symbol, duplicate, or old captures do not mutate detector state. A valid newer RTH capture may intentionally append warmup history, reset on a gap, clear a direction streak, or advance cooldown state without emitting a false alert.
- No scored candidate shows a warning. The user may change preferences or explicitly acknowledge Classic fallback; stale reranked choices are rejected.

## 8. Data/Interface Contracts

- Shared indicator registry JSON is versioned and validated before use. Parameter values are keyed by indicator id and parameter id; geometry is a discriminated union.
- `OrderBookSnapshot` uses sorted finite positive levels, explicit source time and receipt time, provider/capability/freshness metadata, and bounded depth.
- IV alert websocket messages carry authenticated user routing metadata on the server but never expose another user's identifier or state to clients.
- Prisma alert preferences and state use user foreign keys, symbol uniqueness, timestamps, and indexes required by capture processing.
- Scored Auto DTOs carry preset/preferences, selected symbol, candidate freshness, deterministic ranking, exclusions, rationale, runners-up, fallback acknowledgment, and confirmation requirement.
- `OptionContract` gains optional analytics required for scoring without making existing explicit-contract workflows invalid.
- Coordinated breaking migration is preferred to runtime compatibility shims. The only transitional code is an idempotent one-time persisted-settings migration, which deletes the old key after a successful write.

## 9. Observability And Operations

- Structured logs identify provider, symbol, entitlement result, subscribe/unsubscribe reason, coalescing, rate wait, stale transition, reset, detector decision, alert suppression/emission, scorer exclusion, rerank rejection, and order confirmation result without logging secrets.
- Metrics include L2 active symbols/subscribers, provider latency/errors, coalescing ratio, throttle delay, payload bytes, decoder duration, stale counts, alert detector outcomes, alert delivery failures, candidate counts/exclusions, rerank changes, and stale-order rejections.
- Alert on sustained entitlement/provider failures, rate-limit violations, timer/subscriber leaks, capture lag, websocket delivery failure, or abnormal rerank rejection rate.
- Runbooks must explain capability probe, 1 request/sec limit, stale behavior, day reset, detector state recovery, migration rollback, and the physical-device measurement procedure.

## 10. Security, Privacy, And Compliance

- Webull credentials and entitlements are server-side only; logs and websocket payloads must not include secrets.
- L2 and Auto candidate endpoints require authenticated ownership and validate symbols/DTO bounds.
- IV preferences, detector state, and alert delivery are isolated by authenticated user id and symbol.
- Orders remain subject to existing broker ownership, validation, idempotency, audit, and confirmation controls.
- Provider market-data licensing and Nasdaq TotalView non-display entitlement must be documented and verified before production use.

## 11. Acceptance Criteria

- Given either client, when it loads the registry and shared fixture, then it decodes every descriptor and matches expected numeric output within `1e-6`.
- Given two distinct subpanes enabled, when a third is requested, then both clients reject it with the same message and preserve the prior valid state.
- Given no current entitled book, when an L2 view renders, then it says `No L2 data` and never renders a zero-valued substitute.
- Given overlapping L2 subscribers, when requests run, then the provider never exceeds one request/second/app key, work is coalesced, and the final unsubscribe removes timers and work.
- Given paired strikes bracketing spot, when a snapshot is calculated, then ATM IV is exact or linearly interpolated and persisted; missing brackets yield null.

## 12. Risks And Mitigations

- Cross-language math drift: shared fixtures, full-precision calculations, explicit sort order, and `1e-6` parity gate.
- Provider overload or leaked polling: global limiter, coalescing, bounded depth/history, fake-clock lifecycle tests, and active-resource metrics.
- Market-time errors: New York calendar tests covering DST, early close, session reset, RTH, and restart gaps.
- False anomaly alerts: strict pairing/interpolation, warmup, consecutive breaches, cooldown, gap reset, persisted monotonic timestamps, and no backfill emit.
- Unsafe contract execution: hard-filter missing data, explain ranking, require user acknowledgment/confirmation, and rerank fresh on the server.
- Rollback: disable L2 and alert schedulers, restore prior release/database snapshot if migration fails, and keep explicit/Classic selection available; do not restore deleted code as a compatibility layer.
